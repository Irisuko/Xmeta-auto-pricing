# Xmeta 本机跟价助手

在网页中自动检查自己的在售商品，发现其他卖家的更低价后显示建议价。**只有点击“一键跟价”才会提交真实改价。**

## 运行环境

- Windows 10 / 11，Python 3.10 或更高版本，并将 Python 加入 PATH。
- 已安装 Microsoft Edge，或安装 Chrome 作为备用浏览器。
- 首次启动需要联网安装 `requirements.txt` 中的依赖；网页无需 Node.js 或构建步骤。

下载仓库 ZIP 并解压到可写入的目录，或使用 Git 克隆后，按下面步骤启动。

## 使用

1. 双击 `启动跟价助手.cmd`，浏览器打开 `http://127.0.0.1:8765/`。首次显示示例数据。
2. 点击“连接 Xmeta”→“① 打开登录窗口”，在专用的 Xmeta 官方窗口正常登录。登录窗口优先使用 Edge，启动失败时才回退到 Chrome，与系统默认浏览器无关。
   登录窗口初始为较窄的竖向尺寸，页面显示区域随实际窗口大小变化，可以自由拖宽、拖窄或最大化。
3. 登录完成后点击“② 读取我的出售”。这一步只读取数据，不改价。
4. 读取后，同款商品合并成一行，显示在售件数、设定跟价件数和待调件数。可比价商品自动开启跟价，最低售价设为同款当前最低挂单价的 80%（包含自己其他同款挂单，向上取整到分，最低 1 元）。在每款“设置”中修改最低售价和“最低价跟价件数”；默认 1 件，可设置 1 至 100 件。
5. 点击“开始监控”自动检查。核对建议价、待调件数和合计降价后，可点击“一键跟价”，也可勾选多款或全选当前筛选中的可跟价商品，再点击“批量跟价”。两种操作均按每款设定的件数，从自有售价最低的挂单开始选取，其他挂单保持原价。多件任务在列表上方显示逐件进度和结果。
6. 不再使用时，双击 `停止跟价助手.cmd`。关闭网页本身不会停止本机后台检查。

电脑及本机服务需要保持运行；专用登录窗口应保持打开。默认每 60 秒检查一次，最短 30 秒；一次检查完成后才开始计算下次间隔，不会并发轮询。

## 跟价规则

- 按平台和藏品标识合并同款普通单件现货，不按名称合并。未知类型及打包商品保持独立并跳过；同名不同款不会混在一起。
- 每款按自有售价从低到高选取设定的 N 件，并列价格按挂单标识稳定排序。N 包含已经处于低价的件，并非额外再调整 N 件；库存不足 N 件时只取现有件数。检查时挂单、售价或候选计划发生变化，本次操作跳过，刷新列表后再选择；批次中途不替换新挂单。
- 最低价跟价件数、底价、跟价开关、冷却时间按款保存，最低价那件售出后会由下一件继承。该款任一挂单改价结果待确认时，整款暂停跟价，即使待确认挂单已从在售列表消失也不会自动解锁。
- 升级前遗留的待确认挂单若已消失、无法归入同款，会暂停当前账号的跟价；设置中列出待确认挂单标识，核实后可手动解除。
- 自己最低价高于其他卖家时，选中件统一目标价 = 其他卖家同款单件现货最低价 − 跟价幅度，默认少 0.10 元。
- 自己已是最低价或与对手同价时，其他选中件对齐自己的最低价，已有低价件保持原价；没有其他卖家但行情完整时也按自己的最低价对齐。例如自己有 100、100、105 元三件，设定 3 件且对手最低 110 元时，只需将 105 元那件降至 100 元。
- 默认单次最多降 10 元，用户冷却设置默认为 300 秒。真实平台要求同一挂单 30 分钟内只能改价一次（业务码 55040），实际冷却取用户设置与 1800 秒中较长者；已保存的用户设置不改动，演示仍使用用户设置。同款本批已选挂单继续逐件处理，下一次任务遵守平台冷却；若平台因近期手动改价等原因拒绝，另行保存该款 30 分钟等待期限，读取、修改设置和重启都不会清除，页面显示剩余秒数。
- 平台要求每次改价不得低于改价前售价的 20%（业务码 40632）。最终跟价目标先通过个人底价、单次降幅等保护后，若超出平台限制，各件本次先降至原价 20% 的允许价（向上取整到分）；界面同时显示本次价和最终目标。后续仍遵守已设冷却时间，检查后再跟价；程序不会自行跳过冷却或自动提交下一轮。
- 每件分别检查底价、平台下限和单次降幅。目标价低于个人底价、低于 1 元，或超出单次降价上限时，该件保持原价并提示，不用第 N+1 件或其他更高价挂单递补。因此实际待调件数可能少于设定件数。
- 每次手动“读取我的出售”都会重新开启可比价商品，并按当时同款最低挂单价重设 80% 底价，同时保留已设跟价件数。平时使用“立即检查”或定时检查会保留件数、已设底价和手动开关；定时新发现的商品会初始化一次。待确认改价锁定不会被读取操作解除。
- 使用整数“分”运算；不自动涨价，不下架重挂。批量跟价通过逐件改价完成，不调用按藏品整组修改的接口。
- 每批最多选择 100 款，实际需要改价合计最多 1000 件；每款按设定件数展开成逐件任务，页面显示进度、挂单标识和每件结果。普通行情变化或限价不满足会跳过该件；会话变化、连接异常或提交结果不明会停止剩余商品。
- 一键跟价和批量跟价直接复用最近一次“立即检查”、读取出售或定时检查得到的有效行情，开始改价时不再扫描行情。每件只请求平台限价、提交改价、查询该挂单详情确认售价。有效期从各款行情原检查时间计算，点击跟价不会重新计时；本批所用行情达到 240 秒后停止剩余项，提示先点击“立即检查”，不自动再次扫描或继续改价。
- “停止剩余商品”会在当前一件的结果确认后停止后续提交，已成功改价的商品不会回滚。批量执行时不能同时改规则、切换环境或启动另一批。
- 完整读取本人在售列表并展开聚合挂单，排除自己的全部挂单。出售列表请求每页 100 条以减少分页请求和跨页变动；仍校验总数及重复挂单。比价后再次核对本人列表，只暂停库存发生变化的款，保留无关款的有效行情；返回最新库存，已消失挂单移除，新挂单先暂停，等下一次检查。
- 本人库存若出现分页重复、数量变动或聚合数量不符，会丢弃该次不完整结果，再按平台允许的每页最多 200 条完整重读一次，尽量减少跨页边界；仍异常则停止，不会简单去重后继续改价。登录、连接、字段异常不触发此重读，整轮 300 秒预算不重新计时。
- 市场挂单按平台最低价排序逐页读取，完整校验已返回页的价格顺序、重复和分类，找到最低的合格其他卖家报价后即可停止翻页。大量高价挂单不会影响比价；没有找到竞争挂单时必须读完才能判定“暂无其他挂单”。
- 兼容市场返回记录数与 `total` 不一致的情况（实测一页 17 条、总数 16）：已经确认的升序竞争报价仍可用于比价，不按总数截断记录，也不把数量不一致当成完整市场。若没有找到合格竞争挂单且数量不一致，或跨页读取期间总数变化，仅暂停该款，继续读取其他款；本人出售列表仍须完整校验。
- 只处理可确认的普通单件现货（goodsType=1、dealType=0）。打包、预售、未归档、无法识别的商品会跳过。
- 单次读取在每个请求前检查是否超过 300 秒；单个平台接口请求超时为 40 秒，因此读取遇到最后一个慢请求时可能接近 340 秒。后台任务等待上限为 360 秒（6 分钟）。
- 分页不完整、字段异常、请求受限、登录过期或行情超过 240 秒时，不提交改价。
- 额外限价预检兼容实际返回的 `priceStatus=9`、`increaseStatus=9` 且对应边界为空或零的情况；有昨日成交价也可以没有日涨跌幅限制。未知状态或“9”与非零边界同时出现时仍会阻止提交。
- 跟价按面板最近检查的售价、行情及候选挂单执行，提交前校验本地候选计划与价格；若已变化则跳过该项，请核对最新建议后重新选择。缓存有效期内不会重新获取其他卖家的行情或完整库存。同款本批已确认成功的改价不会用新产生的冷却时间阻止其余已选件；下一次任务仍遵守冷却时间。
- 提交后仅查询当前挂单详情，确认身份、卖家和最终售价一致才记录成功，不再为确认一件而扫描全部行情。超时、需要补保证金或无法确认结果时，停止监控并持久保存待确认锁定，不自动重试。
- 平台明确返回 40632（单次改价下限）或 55040（30 分钟间隔）拒绝时，仅撤销本次未接受改价的待确认标记，并显示原始业务提示，批量继续处理其他款。55040 另按款保存等待期限，避免重复提交；未知业务错误、连接异常及结果未确认仍保留锁定。
- 待确认锁定只能在你到平台核实该款所有待确认挂单的最终售价和保证金状态后，通过商品设置里的确认选项解除。随后必须重新检查行情。

## 本机数据

- 服务仅监听 `127.0.0.1`，不部署到网上。
- 登录会话保存在 `.local/browser-profile/` 的专用浏览器资料中；本机服务仅为请求 Xmeta 官方接口读取会话，不将 token 返回面板、不输出到日志。
- 跟价件数、底价、规则、冷却时间及待确认锁定保存在 `.local/config.json`，按已验证卖家标识隔离。检查记录保存在当前服务内存中，可在面板导出。
- `.local/` 和 `.venv/` 已加入忽略清单；不要把 `.local/` 目录发送给其他人。
- 服务重启后恢复到演示环境并暂停监控，需要重新连接真实账号。

## 平台兼容性

平台接入根据 2026-09-13 可访问的官方前端公开代码实现，非平台承诺稳定的公开 API。字段、登录方式或业务限制变化后可能需要更新适配器。官方直接改价流程没有调用 `priceLimits`，本工具把它作为额外保守检查；其双向价格区间字段顺序与通常的 min/max 命名相反，当前会阻止此类真实改价并提示到平台处理。

## 手动启动

也可以在项目目录打开终端，执行：

```text
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe server.py
```

随后打开 `http://127.0.0.1:8765/`。命令行启动时，按 `Ctrl+C` 可退出服务。

## 项目文件

| 文件 | 用途 |
|---|---|
| `launcher.py` | 启动、停止本机服务并打开面板 |
| `server.py` | 本机 HTTP 服务、配置保存、检查及批量任务 |
| `pricing.py` | 金额计算、同款合并、跟价件数与保护规则 |
| `xmeta_adapter.py` | 专用浏览器登录、平台读取与单件改价 |
| `dist/` | 网页面板、样式与交互脚本 |
| `requirements.txt` | Python 依赖 |
| `启动跟价助手.cmd` / `停止跟价助手.cmd` | Windows 启停入口 |

仓库只包含运行程序和使用文档。测试、个人交易明细、登录会话及本机配置不随源码分发；`.local/` 和 `.venv/` 会在本机运行时创建。HTTP 写请求校验来源、Host 与 CSRF，凭据和本机目录不通过静态文件接口暴露。
